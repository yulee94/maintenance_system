# Privacy Compliance Launch Checklist

이 문서는 정비 렌탈 운영 시스템의 정식 런칭 전 개인정보보호, 정보보호, ISMS/ISMS-P 검토 기준입니다. 직원 정보, 고객 정보, 위치 정보, 결제 정보, 출입 기록, CCTV, 건강 정보 등이 들어가면 개인정보보호 이슈가 커지므로 정식 운영 전 반드시 확인합니다.

## 민감도 높은 데이터

아래 데이터가 시스템에 들어가면 개인정보보호, 정보보안, 고지/동의, 접근통제, 보관기간, 파기 기준을 별도로 검토합니다.

| 데이터 | 주요 위험 | 런칭 전 확인 |
| --- | --- | --- |
| 직원 정보 | 근태, 권한, 인사정보와 연결될 수 있음 | 수집 항목 최소화, 권한 분리, 보유기간 |
| 고객 정보 | 담당자 연락처, 사업장 정보, 고객 요청 내용 포함 | 처리 목적, 제3자 제공, 위탁 여부 |
| 위치 정보 | 모바일 앱, 장비 위치, 출퇴근 위치와 연결 가능 | 위치정보 관련 고지/동의 필요 여부 |
| 결제 정보 | 카드, 계좌, 청구, 세금계산서 정보 포함 가능 | 직접 저장 금지 원칙, PG/위탁 계약 확인 |
| 출입 기록 | 출입 시간, 장소, 개인 식별 가능 | 접근권한, 보유기간, 파기 기준 |
| CCTV | 영상정보처리기기 기준 적용 가능 | 안내판, 관리책임자, 열람 절차, 보관기간 |
| 건강 정보 | 민감정보에 해당할 가능성 높음 | 수집 금지 원칙, 필요 시 별도 동의와 법무 검토 |

## 개인정보 처리방침 필수 항목

개인정보 처리방침에는 최소한 아래 항목을 실제 시스템 동작과 맞게 정리합니다.

| 항목 | 확인 내용 |
| --- | --- |
| 처리 목적 | 정비 접수, 배정, 완료보고, 고객 대응, 권한 관리, 보안 로그 등 목적별 구분 |
| 수집 항목 | 필수/선택 항목, 직원/고객/협력사/모바일 앱 데이터 구분 |
| 보유기간 | 법정 보관, 계약 기간, 계정 종료 후 보관, 로그 보관 기간 |
| 제3자 제공 | 본사/사업장/협력사/외부 시스템 제공 여부와 제공 항목 |
| 처리 위탁 | 클라우드, 문자/알림, 이메일, Object Storage, OpenAI/API, 유지보수 업체 |
| 파기 | 계정 삭제, 계약 종료, 보유기간 만료 시 파기 방식 |
| 안전성 확보조치 | 암호화, 접근통제, MFA, 로그, 백업, 망분리/Private Subnet |
| 개인정보 보호책임자 | 책임자 이름, 부서, 연락처, 문의 채널 |
| 정보주체 권리 | 열람, 정정, 삭제, 처리정지, 동의 철회 절차 |
| 자동 수집 항목 | 쿠키, 접속 로그, 기기 식별자, IP, user-agent |
| 모바일 앱 | 기기 식별, push token, 생체인증 사용 방식 |
| AI 기능 | AI에 입력되는 정보, 권한 차단, 외부 API 전송 여부 |

## 런칭 전 Data Inventory

정식 운영 전 모든 개인정보성 데이터를 표로 정리합니다.

```text
data_item
data_subject
collection_source
purpose
required_or_optional
legal_basis_or_consent
retention_period
storage_location
encrypted
third_party_provision
processor_or_subprocessor
deletion_method
owner
```

이 목록이 없으면 개인정보 처리방침, 위탁 계약, 보유기간, 파기 정책을 정확히 만들 수 없습니다.

## ISMS / ISMS-P 검토

KISA는 ISMS-P를 정보보호 및 개인정보보호를 위한 조치와 활동이 인증기준에 적합함을 인증기관이 증명하는 제도로 안내합니다. 규모, 업종, 매출, 이용자 수, 정보통신서비스 제공 여부, 개인정보 처리 규모에 따라 의무대상 여부를 검토해야 합니다.

런칭 전 확인:

- ISMS 인증 의무대상 여부
- ISMS-P 인증 필요 또는 권장 여부
- 자율 신청 또는 고객사 요구 가능성
- 본사/전국 사업장/모바일 앱/클라우드 운영 범위가 인증 범위에 포함되는지
- 외부 협력사와 위탁사가 인증 범위 또는 외부자 보안 범위에 포함되는지

Codex가 도울 수 있는 범위:

- 개인정보/보안 체크리스트 작성
- 데이터 흐름도, DB 항목 목록, API 목록 정리
- 접근권한, `branch_id` 권한 분리, 감사 로그 설계
- MFA, rate limit, 로그인 실패 제한, 파일 접근통제 구현
- 보유기간과 파기 배치 작업 초안 작성

외부 확인이 필요한 범위:

- 개인정보 처리방침의 법적 적정성
- 서비스 이용약관
- 개인정보 수집·이용 동의, 선택 동의, 민감정보 동의 필요 여부
- 위치정보, CCTV, 건강정보, 결제정보 관련 별도 규제 판단
- ISMS/ISMS-P 의무대상 여부 최종 판단
- 위탁 계약서, 제3자 제공 계약서, 국외 이전 고지/동의
- 개인정보 보호책임자 지정과 내부 관리계획 승인

## 정식 런칭 Go/No-Go 기준

아래 항목 중 하나라도 준비되지 않으면 전국 운영 전환을 보류합니다.

- 개인정보 처리방침 초안 작성 완료
- 법무/개인정보보호 담당자 또는 외부 전문가 검토 완료
- 수집 항목과 실제 DB/API/로그 항목 일치 확인
- 보유기간과 파기 정책 확정
- 제3자 제공 및 위탁 현황 정리
- 클라우드, 알림, 이메일, AI, Object Storage 위탁 또는 국외 이전 여부 확인
- 개인정보 보호책임자와 문의 채널 확정
- 관리자 MFA, 접근권한, 감사 로그, 백업/복구 확인
- ISMS/ISMS-P 대상 여부 검토 완료
- 위치정보, CCTV, 건강정보, 결제정보 사용 여부와 별도 요건 확인

## 시스템 설계 반영 원칙

- 개인정보는 목적에 필요한 최소 항목만 수집합니다.
- 급여, 건강, 결제, CCTV 같은 고위험 데이터는 정비 시스템에 직접 저장하지 않는 방향을 우선합니다.
- 직원/고객/협력사 데이터는 `branch_id`와 role scope로 접근을 제한합니다.
- AI 기능은 권한이 없는 사용자의 KPI, 개인정보, 계정/감사 자료 요청을 차단합니다.
- 파일 업로드와 보고서 다운로드는 감사 로그에 남깁니다.
- 개인정보가 포함된 export 파일은 보관기간과 접근권한을 별도 관리합니다.
