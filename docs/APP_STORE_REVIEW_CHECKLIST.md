# App Store Review Checklist

정비 렌탈 운영 모바일 앱을 TestFlight, Play Internal Testing, 정식 스토어 심사에 제출하기 전에 확인해야 하는 항목입니다. 아래 항목은 심사에서 자주 반려되는 사유를 기준으로 작성했습니다.

## 1. 로그인 계정과 테스트 계정

스토어 심사 메모에는 반드시 로그인 가능한 계정을 제공합니다. 계정은 staging API에 연결된 심사용 계정으로 만들고, 심사 기간 동안 비활성화하지 않습니다.

권장 심사용 계정:

| 역할 | 아이디 | 비밀번호 | 확인 화면 |
| --- | --- | --- | --- |
| 최고관리자/관리자 | `ko.ms` | `Admin!2026Test` | 계정 생성, 권한 부여, 승인, KPI, 보고서 |
| 임원 | `kim.ms` | `Exec!2026Test` | 경영 보고, KPI, 최종 승인 |
| 사업장 관리자 | `son.hn` | `Admin2!2026Test` | 작업 배정, 계획업무 승인/반려 |
| 정비사 | `jegal.ts` | `Mech!2026Test` | 오늘 업무, 정비건, 완료보고, AI |
| 접수자 | `park.jw` | `Reception!2026` | 접수/현황 확인 |

운영 제출 원칙:

- 위 계정은 production 실사용 계정이 아니라 staging 심사용 계정으로 운영합니다.
- MFA가 켜져 있으면 심사 메모에 OTP 방식과 임시 OTP를 함께 제공합니다.
- `MOBILE_TEST_OTP_CODE`는 dev/staging 전용으로만 쓰고, prod에서는 TOTP/WebAuthn/SSO MFA로 교체합니다.
- 심사자가 모든 기능을 확인할 수 있도록 최소 1건 이상의 미결, 진행, 완료, 승인 대기, 반려 예시 데이터를 준비합니다.

## 2. 개인정보 처리방침

스토어 등록 전 개인정보 처리방침 URL을 실제 공개 URL로 설정합니다.

필수 포함 항목:

- 처리 목적: 정비 접수, 작업 배정, 완료보고, 계정/권한 관리, 알림, 감사 로그
- 수집 항목: 계정 정보, 사업장/권한 정보, 작업 기록, 사진/동영상 첨부, 기기 식별자, 푸시 토큰
- 보유기간과 파기 기준
- 제3자 제공 및 위탁: 클라우드, 푸시, 크래시 분석, AI API 사용 여부
- 이용자 권리와 문의처
- 개인정보 보호책임자
- 안전성 확보조치: 암호화, 접근권한, 감사 로그, 백업, MFA

앱 설정 기준:

- `APP_PRIVACY_POLICY_URL`: 스토어 개인정보 처리방침 URL
- `APP_SUPPORT_URL`: 지원/문의 URL
- `APP_REVIEW_NOTES_URL`: 심사자 안내 URL

## 3. 권한 요청 설명

권한 요청은 실제 기능 사용 시점에만 띄우고, 왜 필요한지 화면 문구와 OS 권한 문구가 일치해야 합니다.

현재 권한 설명 기준:

| 권한 | 사용 이유 | 심사 대응 |
| --- | --- | --- |
| 푸시 알림 | 작업 배정, 승인 요청, 공지, 장애, 입고/출고, 예약, 정산 알림 | 로그인 후 알림 수신 목적 안내 |
| 카메라 | 정비 완료보고에서 장비 상태, 고장 부위, 교체 부품 사진 촬영 | 완료보고 화면에서만 요청 |
| 사진 보관함 | 기존 현장 사진 또는 동영상 첨부 | 완료보고 첨부 동작에서만 요청 |
| 위치 | 현재 앱에서는 직접 수집하지 않음 | 위치 기능 추가 전 별도 고지와 동의 필요 |

위치 기능을 추가할 때는 다음을 먼저 확인합니다.

- 정확한 위치가 꼭 필요한지
- 백그라운드 위치가 필요한지
- 위치정보사업/위치기반서비스 관련 고지나 약관이 필요한지
- 개인정보 처리방침에 위치정보 항목과 보유기간이 반영되었는지

## 4. 빈 화면과 오류 방지

제출 직전 smoke test:

- 앱 첫 실행 후 로그인 화면 표시
- 모든 심사용 계정 로그인 가능
- 오늘/정비건/완료건/AI 탭 진입 가능
- 정비건 상세 화면 진입 가능
- 완료보고 제출 가능
- 네트워크 오류 시 빈 화면 대신 오류/재시도 안내 표시
- 권한이 없는 KPI/계정/감사 자료 요청 시 AI가 차단 메시지 표시
- 오프라인 큐가 중복 요청 없이 복구 후 동기화
- 푸시 권한 거절 시 앱이 종료되지 않음

Crashlytics 또는 Sentry를 연결한 뒤에는 staging 심사 빌드에서 최소 1회 정상 이벤트 수집을 확인합니다.

## 5. 심사자가 기능을 확인할 수 있게 하는 방법

심사 메모에 다음 정보를 넣습니다.

```text
이 앱은 정비 렌탈 운영 업무용 앱입니다.
심사용 서버: staging API
로그인 계정:
- 관리자: ko.ms / Admin!2026Test
- 정비사: jegal.ts / Mech!2026Test
- 임원: kim.ms / Exec!2026Test
주요 확인 경로:
1. 로그인
2. 오늘 탭에서 배정/긴급/완료 현황 확인
3. 정비건 탭에서 상세 진입
4. 완료보고 작성 및 사진 첨부 화면 확인
5. AI 탭에서 정비 문의와 권한 제한 확인
6. 관리자 계정으로 승인/보고/KPI 확인
결제 기능:
현재 앱은 소비자 대상 인앱 결제나 디지털 콘텐츠 판매를 제공하지 않습니다.
정산 알림은 내부 업무 알림이며 결제 수단 입력이나 외부 결제 유도 기능이 없습니다.
```

## 6. 결제 정책

현재 앱 기준:

- 소비자 대상 디지털 콘텐츠 판매 없음
- 앱 내 카드번호 입력 없음
- 인앱 구매 필요 기능 없음
- 결제/정산 알림은 내부 업무용 알림으로만 사용

향후 결제 기능 추가 전 확인:

- 디지털 콘텐츠/구독 판매이면 Apple/Google 인앱 결제 정책 검토
- 물리 장비 렌탈, 정비비, B2B 정산이면 PG 계약과 전자금융/개인정보 위탁 검토
- 카드번호 원문은 앱과 서버에 저장하지 않음
- 결제정보는 토큰화하고 접근권한과 감사 로그 적용

## 7. 제출 전 책임자 확인

출시 승인 전 담당자가 확인합니다.

| 개인정보 처리방침 URL | 보안/법무 | 제출 전 완료 |
| 권한 요청 설명 | 개발팀 | 제출 전 완료 |

| 결제 정책 해당 여부 | 운영/법무 | 기능 추가 전 검토 |
