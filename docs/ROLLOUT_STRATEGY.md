# Rollout Strategy

이 문서는 정비 렌탈 운영 시스템을 실제 사업장에 배포할 때 순차적으로 적용할 rollout 기준입니다. 추후 배포 단계에서는 아래 순서를 기본 추천안으로 사용합니다.

## 1차: 본사 내부 테스트

본사 내부 테스트는 production 전 최종 운영 검증 단계입니다. 실제 전국 배포 전에 본사에서 기능, 권한, 보안, 운영 절차를 먼저 확인합니다.

참여 대상:

- 본사 관리자
- 운영팀
- 개발팀
- 보안 담당자

확인 항목:

- 로그인
- 권한
- 사업장별 데이터 분리
- 보고서
- 속도
- 오류 로그
- 백업
- 모바일 API

통과 기준:

- 본사 최고관리자, 지역 관리자, 사업장 관리자, 직원 권한이 의도대로 분리됩니다.
- `branch_id` 기준 데이터 분리가 서버 API에서 강제됩니다.
- 보고서와 KPI가 허용된 권한과 사업장 범위 안에서만 조회됩니다.
- 오류 로그와 감사 로그가 운영자가 추적 가능한 수준으로 남습니다.
- 백업과 복구 절차를 staging 또는 검수 환경에서 한 번 이상 확인합니다.
- 모바일 앱이 올바른 API 환경과 연결되고, 토큰 인증과 권한 체크가 동작합니다.

## 2차: 파일럿 사업장 1~3곳

파일럿은 서로 다른 유형의 사업장을 선택합니다. 실제 현장 네트워크, 사용자 숙련도, 업무 흐름 차이를 검증하는 단계입니다.

추천 대상:

- 서울/수도권 1곳
- 지방 대도시 1곳
- 인터넷 환경이 약한 지점 1곳

확인 항목:

- 현장 직원이 실제로 쓸 수 있는가
- 네트워크가 느려도 되는가
- 업무 흐름이 맞는가
- 모바일 앱 알림이 잘 오는가
- 데이터가 본사에서 잘 집계되는가

통과 기준:

- 현장 직원이 별도 개발자 도움 없이 접수, 정비, 완료보고, 알림 확인을 수행할 수 있습니다.
- 네트워크가 느린 지점에서도 주요 화면과 모바일 API가 업무 가능한 수준으로 동작합니다.
- 현장 업무 흐름과 시스템 상태값이 맞지 않는 부분을 정리하고 수정합니다.
- 파일럿 사업장의 데이터가 본사 보고서와 KPI에 정상 집계됩니다.
- 파일럿 기간 중 장애, 문의, 교육 필요사항을 운영 매뉴얼에 반영합니다.

## 3차: 권역별 확대

파일럿 통과 후 권역별로 순차 확대합니다. 한 번에 전국 전체를 전환하지 않고, 권역별 교육과 장애 대응 창구를 준비한 뒤 진행합니다.

확대 권역:

- 수도권
- 충청권
- 영남권
- 호남권
- 강원/제주

권역별 준비 항목:

- 사용자 교육
- 계정 발급
- 장비 세팅
- 모바일 앱 설치 안내
- 사업장 코드와 branch 매핑 확인
- 관리자 권한 확인
- 장애 대응 창구 준비
- 현장 문의 접수 채널 준비

통과 기준:

- 권역 관리자와 사업장 관리자가 담당 사업장만 관리할 수 있습니다.
- 해당 권역의 계정, branch 권한, 장비 목록, 정비 흐름이 정상 동작합니다.
- 장애 대응 창구가 운영 시간과 담당자를 명확히 가지고 있습니다.
- 권역별 교육 자료와 자주 묻는 질문이 업데이트됩니다.

## 4차: 전국 운영 전환

전국 운영 전환은 모든 권역 확대가 안정화된 뒤 진행합니다. 전국 운영 전에는 법무, 개인정보, 보안, 백업, 운영 지원 체계까지 함께 점검합니다.

전국 운영 전 체크리스트:

- 전체 사업장 계정 등록
- 사업장 코드 정리
- 관리자 권한 검수
- 개인정보 처리방침
- 서비스 이용약관
- 장애 대응 매뉴얼
- 백업 복구 테스트
- 모바일 앱 배포
- 고객센터/운영 문의 채널

전국 운영 전환 기준:

- 모든 주요 사업장이 `branch_id`와 사업장 코드로 정리되어 있습니다.
- 본사, 지역, 사업장, 직원, 외부 협력사 권한이 최종 검수되었습니다.
- 개인정보 처리방침과 서비스 이용약관이 실제 수집/처리 데이터와 맞습니다.
- 백업 복구 테스트 결과가 문서화되어 있습니다.
- 모바일 앱의 개발/테스트/출시 채널과 API 환경이 분리되어 있습니다.
- 고객센터 또는 운영 문의 채널이 배포 당일 대응 가능한 상태입니다.

## Rollout 중단 기준

아래 문제가 발견되면 다음 단계 확산을 중단하고 원인 분석과 수정 후 재검증합니다.

- 사업장별 데이터가 섞여 보이는 문제
- 관리자 권한 오작동 또는 과도한 권한 부여
- 로그인 또는 모바일 API 장애가 반복되는 문제
- 보고서/KPI가 실제 운영 데이터와 다르게 집계되는 문제
- 백업 실패 또는 복구 불가
- 현장 업무 흐름을 막는 치명적 UI/API 오류
- 개인정보 또는 민감정보 노출 위험

이번 문서는 전국 배포 확대 기준을 고정하기 위한 문서입니다. 현재 변경에서는 실제 배포 pipeline, 인프라, 모바일 앱, DB schema, API 코드를 수정하지 않습니다.
